# AttendanceApp 2.1.0 implementation and validation audit

Date: 2026-10-20. Source folder: Attendance Project 2.0. No release upload or Git commit was performed. Historical 2.0.4 verification is not counted as current evidence.

The initial measurements below describe the first 2.1.0 delivery. The UI follow-up verification section at the end records the subsequent flicker/settings revision and supersedes its binary/storage measurements. The 2026-10-21 desktop verification below is the latest result.

## Implemented changes

| Subsystem | Delivered behavior |
| --- | --- |
| Attendance | Present/Absent/Late/Other/Leave/Pending; Pending initialization; required notes for Other/Leave; notes retained for every state |
| Workflows | Selected-row batch status/note operations; reasoned make-up attendance; exact searchable lessons; rename/copy; courses from roster/metadata templates |
| Transactions | Validate before commit, one undo step per operation, duplicate-target rejection, missing/duplicate make-up detection |
| Statistics | Present / (Total - Leave - Pending), No data on zero denominator, calendar weeks, exact current-course profiles and current-period risk summaries |
| Storage | V6 defaults, V1-V5 reading, separate annotated V5 downgrade, overwrite-time migration safety copies, atomic writes |
| Reports | Six-state CSV/HTML/PPTX/database output, current-period snapshots for course reports, six-state charts and 64-bit chart arithmetic |
| Recovery | Ordinary history count/byte rotation; protected recovery retained when capacity prevents replacement |
| Builds | VERSION-driven headers/resources/manifest; static MSVC runtime; opt-in tests; reusable object modules; Visual Studio object-only Lib-task override |
| Storage tooling | 512 MiB sampled generated-artifact guard; fixed owned test directory; 20 MiB total / 5 MiB per-file test limits; safe preview-first cleanup |
| Documentation | All 5 maintained pre-existing Markdown documents updated; 3 new documents; 5 obsolete snapshot documents removed with their snapshots |

New C++ modules are core/status, model/operations, ui/choice, app/workflows and storage/backup_policy. Build/resource templates, helper scripts, current model/UI/report paths and regression tests were updated together. The retained resource entry files point to the generated-resource workflow; their direct deletion was rejected by automatic approval review, so a nondestructive compatibility approach was used.

## Measured disk use

| Measurement | Logical bytes |
| --- | ---: |
| Project before implementation | 7,926,751 |
| Explicit old snapshot/cache/release cleanup | 6,728,282 removed |
| Measured redundant static archive | 182,707,046 |
| Original static-archive build directory | Approximately 384 million |
| Final shared-object build directory, before cleanup | 202,200,782 |
| Sampled final build peak | 202,428,066 |
| Packaged application executable | 1,048,064 |
| Project after compiler cleanup | Approximately 6.0 MiB; final exact size is recorded in the delivery validation JSON |

MSVC compilation objects were about 184 MB, and the static archive duplicated almost all of them. This establishes a reproducible source of large build caches: multiple such trees can total GB. The previously deleted GB-scale files were unavailable, so this is not proof of which historical files consumed that space.

CMake OBJECT alone still caused the Visual Studio generator to run its librarian. An AttendanceRuntime-only ForceImportAfterCppTargets import now suppresses that redundant Lib task; applications explicitly link the objects. This was verified by a successful app/test rebuild with the archive absent. No toolchain installation or system MSBuild file was modified.

Compiler caches were removed after validation. Release/direct executables, the small test executable, generated version resources, summaries and the current release package remain. The next build regenerates compiler intermediates. No GB-sized test fixture was created.

## UI follow-up verification - 2026-10-20

This section records the subsequent operation/settings/theme-flicker revision. The version remains 2.1.0, and both local Release executables and the release ZIP were rebuilt from the revised sources.

### Implemented

- Replaced the Interface Settings / Advanced personalization split with one Settings form. All existing preferences remain available. Labels sit above values; wide/narrow layouts, scrolling, row-major Tab order, automatic focus scrolling and shared Reset / Apply / Close actions use the same form. The obsolete heading/control/expansion code is removed; existing preference file keys remain compatible.
- Added visibility-preserving, nested UI redraw scopes. A cached/prewarmed hidden settings window is no longer made visible by WM_SETREDRAW(TRUE). Reopening an already visible settings window raises it without relayout or reset.
- Buffered buttons, toggles, statistics cards, headers and closed combo frames; settings child painting is composed (the main-window composition was subsequently removed; see the 2026-10-21 verification). Statistics skip unchanged text and no longer force a parent paint before each label. Native edit hover redraw is limited to the border. Routine record/filter refreshes no longer restart a full-table reveal.
- Theme updates queue complete paints, retain intermediate/reversible palette animation, avoid frame reconstruction and reuse unchanged native themes. Selecting a theme no longer rebuilds combo contents or moves the settings window. Autosave interval and grid/display options update the affected timer/controls.

- Native off-screen fixtures and in-memory GDI surfaces checked hidden creation/prewarm/language refresh, nested redraw ownership, unchanged text, no synchronous text paint, edit-client invalidation, buffered pixel commit/clipping, 520/1040-pixel settings bounds, bottom actions, tab order, focus scrolling, unchanged native-theme calls and theme selection without combo reset/window movement. Deterministic intermediate frames, rapid reversal and final palettes passed. - All existing small regression/storage/report cases also passed three final repetitions: 129,569 / 129,568 / 129,565 bytes per run before cleanup. Largest file: 72,035 bytes; test scratch removed; no growing per-run directory or payload.
- Architecture: 58 implementation files, 62 headers, 555 local includes. Localization: 31 new feature keys across 20 languages, 268 currently scanned Hong Kong call-site keys; generated-catalog consistency passed. Eight maintained Markdown documents / 17 local targets checked.
- Release/package parsers and both project/package association discovery passed. Package executable hash matches the CMake Release executable. Compiler caches were removed after verification; exact final bytes and package SHA-256 appear in the accompanying delivery JSON.

## Desktop follow-up verification - 2026-10-21

This is the current verification record for the final 2.1.0 package. The earlier Computer Use denial is historical: access worked during this session. The earlier binary sizes, test repetitions and desktop limitations above apply only to those dated builds.

### Corrected after desktop inspection

- Removed whole-window WS_EX_COMPOSITED from the main window after observing missing titles, statistics, fields and buttons. An explicit child-tree repaint at first show alone did not resolve that defect; removing main-window composition did. Per-control buffered drawing remains, and Settings retains its verified composed layout. Both windows explicitly paint their child tree after hidden initialization.
- Added the Common Controls v6 manifest to both application and test executables. The native fixture verifies the list control's actual DLL version. Windows documents that [LVS_EX_DOUBLEBUFFER requires version 6 or later](https://learn.microsoft.com/en-us/windows/win32/controls/extended-list-view-styles); the previous manifest omitted that dependency.
- Removed obsolete experimental/advanced-section control IDs and the remaining particle exclusion reference. The single Settings form retains all preferences and contains no Advanced personalization heading.
- Fixed Apply saving a changed language without immediately translating the interface. The regression now verifies immediate label changes and preserved hidden-window visibility.
- Completed 23 appearance/settings translation keys across 20 languages, including 22 missing shared-catalog entries. Missing legacy translations outside Simplified Chinese fall back to English. German inspection had exposed Chinese fallback text; the corrected settings form was inspected again.
- Preserved bounded failure-log tails in the test/build exception so failed assertions remain visible after scratch cleanup. Hidden layout tests check geometry and visibility; they do not assume Windows retains an update region while a window is hidden.

### Executed for the final sources

- CMake Release application and tests built successfully with native analysis enabled. The earlier full runtime analysis and final incremental analysis reported no warning diagnostics. Direct MSVC Release rebuilt separately. Both binaries are 1,059,328 bytes, version 2.1.0. The CMake PE imports contain Windows system DLLs and no separate MSVC C++ runtime DLL.
- Three final isolated regression/storage/report runs passed: 129,565 / 129,567 / 129,565 bytes before per-run cleanup; largest file 72,035 bytes. All existing small model/storage/report tests and the native UI cases ran. Test scratch and preview data were removed.
- Native UI cases include nesting/hidden visibility, moved hidden children, buffered pixel presentation/clipping, text/update behavior, settings geometry/tab/focus, language Apply, German fallback, effective Common Controls v6 activation, theme midpoint/reversal and completion.
- Computer Use inspected English, Simplified Chinese, Hong Kong Traditional Chinese and German main/settings views on the current desktop. Settings opening, scrolling to shared actions, closing, light-theme application, grid toggling and adding a disposable Present record were exercised. The record appeared in the list and the count/rate updated to 1 and 100%. Theme and language choices were also exercised through the supported accessibility value interface followed by Apply. Some transient input/state bindings required fresh window selection; completion was checked in the refreshed view.
- Architecture: 58 implementation files, 62 headers, 555 local includes. Translation checks: 31 feature keys plus 23 settings keys across 20 languages; 268 Hong Kong call-site keys. Catalog regeneration consistency and eight Markdown documents / 17 local targets passed.
- CMake, direct and packaged parser/version checks passed. Project/package executable discovery passed with --check; registry associations were not installed. The staged executable SHA-256 matches the CMake Release executable.
