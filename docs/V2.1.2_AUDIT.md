# AttendanceApp 2.1.2 LTS verification audit

Date: 2026-11-12. Baseline: `9e42bf99899b5719eac43e84894de7b4ad0e2729` on `2.1LTS`.

This is a maintenance release. Student identity, lesson labels, the V6 layout, V1-V5 readers and V5 downgrade semantics are retained. Student IDs, structured dates, audit trails and encryption remain outside this release. The pre-existing local deletion of `src/main.cpp.backup-combo-theme` is excluded from the release commit.

## Desktop verification and English images

Only synthetic data and an isolated `ATTENDANCEAPP_DATA_DIR` were used. Eighteen courses contain fictional English names; the displayed course has 12 roster members and 48 records, with 28 Present and four of each remaining status. Eligible records total 40, so the expected attendance rate is 70.0%. The chart and exported HTML agree with these counts.

Observed in the candidate program: English dark/light main windows; shared course, settings-theme and font popups; selected font visibility; menu scrolling; Settings top/bottom with fixed title/footer; reopening Settings; quick-roll-call progress after marking Present; rejection of Leave without a note; explicit cancellation without committing the session; six-state chart; HTML export success and rendered English report. The candidate was closed and reopened with isolated appearance preferences.

The eight published images are original screenshots from this 2.1.2 build and its HTML output. They were not redrawn or translated. Interface language, course data, notes and captions are English. Images are tracked in `docs/images/v2.1.2/`; the same README and display resources are synchronized to `main` without merging LTS application code.

The final ZIP was extracted into a separate folder and its executable was launched against the isolated synthetic workbook. English large text / spacious density / standard motion was inspected in the main window, maximized window and Settings. German small text / compact density / motion off was inspected in the main window and Settings as an internal long-label check. Normal text/density with advanced motion was used for the English screenshot set. Internal multilingual evidence is not included in the README or Release gallery.

A half-screen main window was observed with the existing scrollable canvas and horizontal scrollbar; content beyond the narrow viewport is intentionally reached by scrolling. This is a limited viewport observation, not a full snapped-window input pass. Both extracted-package sessions closed cleanly.

## Coverage limits and exclusions

- **Windows scale changes were cancelled at the user's request.** The existing 100% setting was viewed but never changed. 125%, 150% and 200% desktop scaling are not verified for this release.
- The desktop wrapper activates/restores the main window before input. This limits reliable keyboard input into some owned windows, selection in Settings popups and persistent snapped/maximized interactions. Native live-message-loop checks cover the affected routing paths; they are not described as manual GUI passes.
- Full physical IME candidate selection, a clean Windows machine, multiple monitors, high-speed frame recordings and native-speaker review of all 20 languages remain unverified.
- The application still copies/validates whole candidate workbooks and keeps bounded history. Synthetic tests are intentionally small; this audit does not establish responsiveness at maximum production limits.
- CSV apostrophe protection concerns the initial export. Different spreadsheet applications and subsequent editing/re-saving can change interpretation. `.attd` and the database mirror retain exact field text.
- Offline files remain XOR/Base64-obfuscated, not cryptographically encrypted. No new identity, privacy or institutional audit capability is claimed.
