# AttendanceApp 2.0.4 (Ultra Optimization): Implementation Audit

Date: 2026-10-15. Baseline: the local 2.0.3 source and executable preserved in `build/baseline-2.0.3-ultra` before implementation.

This document distinguishes implemented changes, measured results, and remaining validation. It is not a claim that every possible defect has been eliminated.

## Compatibility and Scope

- Production code now has 52 independently compiled `.cpp` files and 56 headers across app, core, model, storage, settings, UI, animation, localization, reports, and test support. `main.cpp` is an entry-point wrapper, not a textual include of the original monolith.
- Five explicit state owners replace scattered mutable globals. The active course owns its records; a second full mutable record vector is no longer maintained.
- Business commands, control IDs, shortcuts, overall layouts, `.attd` V5 output, V1-V5 import, and the existing 20 languages are retained.
- Personalization is generally available. The experimental toggle and confirmation flow are removed. The legacy `advanced_personalization` key is accepted but no longer hides controls or resets a saved theme.
- Dropdown scroll scheduling supports 60-360 FPS, defaulting to 60. This is the user's clarified request, not an increase in particles. Existing low/medium/high particle counts, appearance, and effect switches are unchanged.
- Numeric FileVersion and ProductVersion are `2.0.4`; the application title is `AttendanceApp 2.0.4 (Ultra Optimization)`.
- README remains English. No release was uploaded and no Git commit was created.

## Confirmed Fixes by Severity

### T0: Data Safety and Major Reliability

| Defect or risk | Change | Evidence |
| --- | --- | --- |
| Disabling the startup recovery prompt could allow an existing recovery file to be overwritten | Protect an existing autosave before evaluating whether the prompt is enabled; preserve it in a protected backup before cleanup/replacement | Regression restores the exact original recovery bytes from the protected backup |
| Explicit save cleanup could remove an ignored recovery file or prematurely permit overwrite | Archive protected recovery first; enable overwrite only after successful cleanup | Recovery and atomic-write regressions |
| An exception during file generation could leave temporary files behind | RAII temporary-file cleanup and failure return; the existing destination is not replaced after a failed writer | Injected false return and exception both preserve `original` bytes |
| Temporary-file names could collide, and simultaneous replacements of the same target could compete | Process/tick/atomic-sequence temporary names; serialize only final replacement commits | Two threads each perform 20 writes; final content is one complete payload and no temporary files remain |
| Size/count declarations could cause unnecessary allocation before truncation was recognized | Exact bounded file reads, decoded-size checks, count-to-source-size sanity checks and pre-serialization size budgeting | Parser regression, oversized/truncated input, V1-V5 compatibility, bounded-read test |
| A main message-loop error could bypass normal worker/window teardown | Explicitly tear down a still-live main window after the loop and attempt autosave on error | Code review and native static analysis; OS message-loop failure not fault-injected |

### T1: Interaction and Performance

| Defect or inefficiency | Change | Evidence |
| --- | --- | --- |
| Frequent animation wakeups could postpone a pending frame indefinitely | Preserve the current frame deadline on wake; skip expired frames without advancing twice; reuse dispatch buffers | Continuous-restart scheduler regression and 60/120/240/360 timing samples |
| Restarting an animation while the worker had an older timestamp could underflow unsigned elapsed time | Clamp elapsed time to zero before interpolation | Code review and scheduler tests |
| Ctrl+K could be lost when a child input had focus | Route command-palette activation through the global shortcut preprocessor | Code review; Ctrl+S with input focus was also checked through Computer Use |
| Batch deletion repeatedly shifted the same record vector, and invalid/duplicate indices were unsafe inputs | Validate, deduplicate and compact once; preserve a single undo operation | Invalid/duplicate deletion, undo and redo regressions |
| Record synchronization and quick-roll-call lookup repeatedly copied or scanned large data sets | One canonical active record vector; indexed per-student roll-call lookup with duplicate ambiguity retained | Source audit, codec/filter benchmarks, existing roll-call validation paths retained |
| Unchanged dirty workbooks were re-encoded and written at every autosave interval | Track revisions and skip an already-autosaved revision | Changed/unchanged/subsequent-edit autosave regression |
| Advanced search rebuilt its query and allocated lowercase strings for every row | Cache parsed query terms; use allocation-free case-insensitive matching | Baseline-equivalent results at 1-10,000 students / 10-100,000 records |
| Report generation and file writes ran directly in the button handler | Snapshot data and localized labels, generate CSV/HTML/database content on a worker, and perform PowerPoint packaging/writing on that worker | Four-format snapshot isolation, correct worker/UI thread routing, bounded queue, worker failure, snapshot-allocation failure, shutdown-write tests, and an actual CSV export through Computer Use |

### T2: UI and Report Rendering

| Defect | Change | Evidence |
| --- | --- | --- |
| Rows farther down the table could remain in an unfinished reveal state | Calculate reveal relative to the visible range and fully reveal every row at animation completion | Drawing-path review |
| Settings could calculate its scroll range only from the left column | Include both columns when computing content height | Layout review and normal-size dark/light settings screenshots |
| Longer setting labels had an unnecessarily fixed width | Measure the current font and translated labels within the existing column constraints | Layout review; exhaustive DPI/font coverage remains pending |
| Selection indices could carry over to unrelated courses or loaded/restored workbooks | Clear stale visible-row mappings at data-source changes | Selection/history path review and history regression |
| PowerPoint status bar widths overflowed a 32-bit product with large record counts | Use 64-bit multiplication before scaling the width | Regression checks expected maximum width; all 20 XML/relationship parts parse and shape extents are nonnegative |

The chart correction intentionally changes incorrect bar geometry in large reports. Output from those reports should not be expected to have the old binary hash.

### T3: Resource, Validation and Build Details

- Reuse fonts when family and scale are unchanged; preserve the previous font handles if replacement creation fails.
- Track applied font-list generation so reopening Settings does not rebuild an unchanged installed-font list.
- Avoid full visual refresh when only nonvisual preferences change.
- Reject malformed function-key shortcut strings such as `Ctrl+F1junk`.
- Report default-folder save success only after the settings write succeeds.
- Use a static CRC32 table, checked ZIP sizes/counts, moved ZIP entries, and indexed date aggregation.
- Remove the empty close-cancellation function and unused XML helper. Retain compatibility keys and runtime test hooks.
- Refuse to continue a build when an old output cannot be removed; do not mistake a locked stale executable for a new build.
- The direct MSVC fallback compiles all modules to distinct object paths and uses the same DLL runtime and Release optimization policy as CMake.
- Store localization tables as deduplicated UTF-8/UTF-16 pools with 32-bit offsets instead of repeated 64-bit pointers. Editable catalog JSON and a deterministic generator are included; no runtime decompression or extra startup allocation is required.

## Measurements

Same machine, Release builds, same generated inputs, one warm-up plus five samples per operation; the median is reported. Baseline and new binaries run sequentially, after builds finish. These are synthetic core-operation timings, not whole user-workflow latency guarantees.

For 10,000 students and 100,000 records:

| Operation | 2.0.3 | 2.0.4 | Observation |
| --- | ---: | ---: | --- |
| Serialize workbook | 58.692 ms | 37.397 ms | About 36% less time |
| Validate and encode workbook | 116.012 ms | 85.310 ms | About 26% less time |
| Decode payload | 29.792 ms | 30.855 ms | About 4% more time in this run; no decoding speedup claimed |
| Parse decoded workbook | 153.157 ms | 84.899 ms | About 45% less time |
| Advanced filter | 130.271 ms | 16.308 ms | About 87% less time |
| PowerPoint export, including disk write | 27.758 ms | 11.847 ms | Highly variable; an earlier new-build run measured 49.891 ms. No stable end-to-end export speedup is claimed |

The final CMake executable is **702,976 bytes**, versus the preserved baseline's **715,776 bytes**: 12,800 bytes smaller, approximately **1.79%**. The direct-MSVC validation build also measured 702,976 bytes. No packer is used and particle density is not reduced.

Scheduler median message intervals in the final run: 16.657 ms at 60 FPS, 8.310 ms at 120 FPS, 4.137 ms at 240 FPS, and 2.776 ms at 360 FPS. These measure dispatch to a test message window, not physical display presentation or actual 360 FPS GDI rendering.

## Completed Verification

- CMake `build.bat` Release build and direct-MSVC fallback: passed, with `/W4`.
- Native Code Analysis: the final full rebuild passed after the initialization fix and explicit annotation of the RAII lock-release invariant. No analysis warnings were emitted.
- CTest regression: passed, including the existing malformed-file suite, V1-V5 imports, round trips, strict shortcuts, settings migration, invalid FPS boundaries, failed/concurrent writes, autosave protection, batch history, CRC32 and chart geometry.
- Baseline/new translation checksums match across all 20 languages for the existing test-key corpus. The intentionally changed frame-rate label is excluded from that comparison and independently checked for `360` in every language.
- Hong Kong release validation: 263 dictionary entries, all 257 currently required keys covered.
- Header dependency checker: 482 local includes checked; all resolve, no production `.cpp` includes, no header include cycles. The scanner also fails if it finds no includes, preventing an ineffective scan from passing. This does not mean the application has been rewritten as a strictly one-way layered dependency graph; shared types and some cross-module calls remain.
- Final FileVersion/ProductVersion checks: `2.0.4`.
- Computer Use: actual dark and light main/settings windows, visible personalization controls, retained light configuration with the old experimental key set to zero, visible 360 FPS setting, adding a test attendance record, Ctrl+S with input focus, a completed CSV export with file-content verification, closing Settings, and first-click main-window close with no remaining process.
- All live tests used workspace-local test AppData and generated records. Real user workbooks and settings were not modified.

## Remaining Work and Validation Limits

- Report jobs are bounded to two outstanding snapshots. An additional request is rejected through the existing export-failure path rather than accumulating memory. Accepted writes finish during shutdown; no completion dialogs are shown after the owner closes.
- Snapshot capture, PowerPoint slide assembly, and `.attd` import/save remain synchronous. CSV/HTML/database generation and report disk writes are asynchronous. This is not a claim that every part of every file operation runs off the UI thread.
- The Computer Use helper returns Settings inside the parent's tree but rejects its child element indexes (`element ... is not available in cached app state`). Reactivating the parent also changes dropdown/focus state. Therefore exhaustive interactive typing, live theme reversal and continuous dropdown scrolling were not established with this helper; automated settings/scheduler tests do not replace that visual validation.
- The legacy PowerShell UI-automation smoke script was not executed in this turn. Computer Use was used for desktop interaction instead.
- No exhaustive 100%-200% DPI, multi-monitor, precision-touchpad, every-font/every-language screen review, full manual roll-call matrix, or long-duration CPU/GDI/USER-resource soak was completed.
- Startup latency and Settings-opening P95 were not measured against the preserved binary. No improvement is claimed for those metrics.
- No power-loss or physical disk-full fault injection was performed. False-return, exception, bounded-read and concurrent-writer paths were tested instead.

These outstanding items are release-validation gaps, not evidence of confirmed defects or guarantees that no defects remain.
